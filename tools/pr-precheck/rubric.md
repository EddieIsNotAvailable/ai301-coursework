# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-fidelity | Plan context or plan.md scope, promised outcomes, and Deviations alongside the complete diff and PR description | Every material addition and omission matches the plan or is explicitly disclosed with a reason in the package's deviations/PR notes; the description accurately states what the diff delivers. An honestly disclosed shortfall can pass; silent extra behavior, missing promised behavior, or a contradicted fidelity claim fails. | required |
| behavioral-evidence | Reproduction and plan test plan alongside candidate Test evidence or test_evidence.md and PR Testing | Concrete executed commands and observable before/after results distinguish the issue's failure from the expected behavior through the real affected path, with relevant controls. Cover the materially distinct planned triggers or explicitly disclose an unrun case and its limitation without claiming full coverage. Added tests, checkboxes, bare 'tests pass', and comment-only assertions are not executed evidence. | required |
| repository-checks | Repo facts' stated checks and plan test plan alongside test output and PR Testing | Required repository checks have identifiable commands and recorded outcomes. Honest failures or unavailable checks can pass when the reason and remaining limitation are stated; an expected empty integration suite is disclosed rather than called passing. An unexplained omitted required check or unsupported green claim fails. Do not invent a suite requirement when the repository states none; use the applicable planned verification. | required |
| reviewable-diff | Entire unified diff, changed files, and commit list paired with issue and plan boundary | The fix is visible and bounded to the issue; no debug prints, dead/commented-out code, unrelated edits, or avoidable bulk formatting bury it. An explained implementation deviation can be relevant, but disclosure alone does not excuse unrelated cleanup. | required |
| repo-standards | Repo facts' template asks and policy, issue/thread directions, or live PR template and docs/CONTRIBUTING.md against title and description | The PR supplies substantive answers to stated template asks, references its issue, and follows explicit maintainer instructions and stated contribution/AI-disclosure requirements. Apply disclosure only when explicitly required by the repository or course in live mode; do not invent one for eval repos with no stated requirement. Clearly justified N/A and honestly unchecked unrun CI are acceptable. Boilerplate, missing required content, and ignored explicit asks fail. | required |
| reviewer-context | Title and description alongside diff and test evidence | The title names the changed behavior and the description makes the reason, validation, and remaining limitations easy to find without exaggeration. Terse but complete text passes; length and polished phrasing earn no credit by themselves. | preferred |

## Verdict rule

Accept exactly when every required check passes. Any required fail or unclear yields reject. Preferred failures or unclear grades are advice and never change the verdict. Grade unclear when deciding evidence is genuinely absent or inaccessible, and fail when available evidence contradicts the pass condition. An honest disclosed shortfall is judged by the checks above, not automatically rejected.
