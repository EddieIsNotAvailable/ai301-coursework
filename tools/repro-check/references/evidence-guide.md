# Evidence guide: where proof lives in a reproduction package

## Environment

What good looks like: The report records the relevant package versions and any configuration information, along with the OS version for OS specific issues

## Steps

The steps are sufficient if following them is enough to recreate the reported outcome

## Behavior shown

The artifact shows the same failure, output, or observable behavior described by the issue, with enough context to identify the command or action that produced it. A different error or an unrelated warning does not count as a match.

## Honesty

Compare the claim comment and repro report with the issue context and the evidence they quote. The wording should only state what the recorded steps and artifacts support. A genuine cannot-reproduce result is reported as such with the attempted environment and steps; the report does not claim reproduction, a fix, or a cause that the evidence does not show.

## Comms

The comments name the specific issue and report concrete observations instead of boilerplate. They follow required templates and disclose AI assistance when the repository's stated policy requires it.
